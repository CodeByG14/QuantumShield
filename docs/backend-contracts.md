# QuantumShield — Engine and database contracts

This document defines the contracts to settle before implementing the HTTP API. It does not implement FastAPI routes or input processing.

## Identifiers are deliberately separate

| Identifier | Lifetime | Purpose |
|---|---|---|
| `session_id` | Local browser session | Internal database identity for the anonymous local UI session. The browser receives a high-entropy cookie token; the database stores only its SHA-256 hash in `local_sessions.token_hash`. |
| `project_id` | Persistent project | UUID primary key in `projects`; the same logical project can have many scan runs. |
| `scan_run_id` | One scan attempt | UUID primary key in `scan_runs`; records status and input metadata. |
| `workspace_id` | One temporary workspace | Random UUID used as a safe temporary directory name, for example `/tmp/quantumshield-workspaces/<workspace_id>`. Generate a fresh value per scan; never use this as `project_id` or `assessment_id`. |
| `assessment_id` | One assessment result | Generated by the engine for a completed scan and used by existing plan, compliance, and diff operations. |
| `migration_plan_id` / `report_id` / `diff_id` | One generated artifact | Identifier for a stored migration plan, compliance report, or saved comparison. |

A temporary directory is an implementation detail, not the project identity. The persistent `project_id` is generated once for a logical project; a fresh `workspace_id` is generated for each submitted source. Equivalent scans from different workspaces must still be comparable. Keep the existing regression test covering comparison across separate temporary roots.

## Supported input contract

`quantumshield.source_contracts.ScanSourceMetadata` is metadata only. `quantumshield.storage_contracts.assessment_snapshot_for_storage()` defines the safe assessment JSON shape stored in `assessments.assessment_json`. Its `input_kind` values align with the database `scan_runs.input_kind` field:

- `github_repository`: `source_reference` is an HTTPS URL on `github.com` identifying an owner/repository; record the resolved commit in `source_revision`.
- `zip_archive`: `input_name` is a sanitized upload filename; `source_fingerprint` can hold the SHA-256 of the uploaded bytes.
- `sbom`: an uploaded, explicitly supported Software Bill of Materials document.
- `cbom`: an uploaded, explicitly supported Cryptography Bill of Materials document.
- `local_directory`: internal/test-only engine input; do not expose it as a public HTTP input in the first version.

For ZIP, SBOM, and CBOM inputs, `source_reference` remains null. Never persist credentials, tokens, URL query strings/fragments, uploaded source bytes, or absolute temporary filesystem paths in the source metadata. Input parsing/extraction and format support are later service-layer responsibilities; this metadata model does not claim those adapters already exist.

## Assessment contract

- `AssessmentResult.schema_version` is `1.0` for the first explicit assessment payload schema. It is separate from `policy_version`.
- `assessment_schema_version` in PostgreSQL is populated from `AssessmentResult.schema_version`; do not hardcode a different version in the API layer.
- The engine's `scan()` still receives a real absolute directory path because discovery needs a filesystem root. `project_name` is a logical display name supplied from the persistent project record, not inferred from the random workspace folder.
- `context_loaded` is separate from `project_name`. Supplying a project name from the database must not imply that risk context was supplied. Pass `context_loaded=False` if the request only supplies the project name and no risk context; pass `True` only when the user supplied validated risk context.
- The in-memory engine result can retain its actual target path while scanning/comparing. `assessment_snapshot_for_storage()` in `quantumshield.storage_contracts` creates a storage-safe copy: it replaces the top-level `target` with `project:<project_id>`, leaves the in-memory engine model unchanged, and rejects absolute evidence paths. Use the returned copy for `assessment_json` and the API response. Finding evidence paths are project-relative. Never store or expose the random temporary absolute path.
- Keep the engine-created `assessment_id` distinct from the database's `scan_run_id`; store their relationship using `assessments.scan_run_id`.

## Database contract

Migration `002_local_sessions_and_source_contract.sql` builds on applied migration `001_initial.sql`; do not edit the applied `001` file.

- `local_sessions.token_hash` stores SHA-256 of a high-entropy random cookie token, not the raw token. Set an HTTP-only, strict same-site cookie; the session is a local workspace convenience and is not real user authentication.
- Every new project created by the future API must have a `projects.session_id`. Existing rows remain nullable for migration compatibility; the API must never list unowned rows to a session.
- `scan_runs.workspace_id` stores only the random UUID, never the directory path. The worker derives the path from a fixed configured workspace root and that UUID, then cleans the directory in success and failure paths.
- `scan_runs.source_reference` is for a sanitized public GitHub repository URL only. Store the resolved commit separately in `source_revision`.
- Keep `assessment_json` as a complete versioned snapshot. `assessment_findings` is a searchable projection of findings and risk values, not a replacement for the snapshot.
- Persist an assessment snapshot and its finding projections in one transaction. Only mark a scan completed after that transaction succeeds. On errors, persist a sanitized error summary and mark the scan failed.
- A comparison must use two different saved assessment IDs and persist its `diff_json` plus summary. Verify both assessments are accessible to the current local session through their project/scan relationships before comparing.
- A compliance report's optional migration plan must belong to the same assessment. Verify this in service logic before calling the engine.

## Future API input mapping (not implemented here)

The first `POST /scan` contract will use multipart form fields: `source_type` (`github_repository`, `zip_archive`, `sbom`, or `cbom`), a repository URL for GitHub, or one uploaded file for the other three kinds. Optional project-context fields are validated separately. The API will use unversioned root-level routes such as `/scan` and `/diff`, as requested.
